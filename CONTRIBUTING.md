# Contributing

Спасибо, что хотите доработать `tg-tree-wizard`. Ниже — как поднять проект
локально, погонять тесты и что важно сохранить в архитектуре при PR.

## Установка для разработки

```bash
git clone https://github.com/I1obody/tg_tree_wizard.git
cd tg_tree_wizard
python -m venv venv
source venv/bin/activate        # Windows: venv\\Scripts\\Activate.ps1
pip install -e ".[dev]"
```

`-e` (editable) — пакет ставится "по ссылке" на исходники, изменения в
`src/tg_tree_wizard/` сразу видны без переустановки.

## Тесты ядра (без Telegram, без сети)

```bash
pytest tests/ -v
```

Ядро (`core.py`) тестируется напрямую, без единого объекта aiogram —
это осознанное архитектурное решение, см. ниже.

## Прогон через настоящий aiogram, но без сети

```bash
python examples/simulate_flow.py
```

Использует настоящий `Dispatcher` и `MemoryStorage`, подменяет только
реальный HTTP-запрос к `api.telegram.org`.

## Запуск примеров с реальным ботом

```bash
export BOT_TOKEN=ваш_токен
python examples/pizza_bot.py
```

## Архитектурное правило: core.py не должен знать про aiogram

`src/tg_tree_wizard/core.py` — чистая логика (переходы по дереву,
"назад", валидация) без единого импорта `aiogram`. Вся интеграция с
Telegram — в `aiogram_adapter.py`, тонким слоем поверх ядра.

Если ваш PR добавляет фичу, для которой мысленно тянет добавить импорт
`aiogram` в `core.py` — это сигнал, что фичу либо нужно спроектировать
как чистую функцию/данные (и передать конкретику в адаптер), либо она
целиком принадлежит `aiogram_adapter.py`. Это правило и делает ядро
тестируемым за миллисекунды без сети — ломать его не стоит.

## Semver

Начиная с `1.0.0` публичный API (`Node`, `Option`, `WizardState`,
`TreeWizard`, `linear_wizard`, `pack_buttons`, `check_callback_data_limits`)
считается стабильным. PR, меняющий сигнатуры этих функций/классов —
ломающее изменение, обсуждается отдельно перед мержем.

## Процесс PR

1. Форкните репозиторий, создайте ветку от `main`.
2. Убедитесь, что `pytest tests/ -v` проходит целиком (CI это тоже
   проверит автоматически на 3.10/3.11/3.12).
3. Если добавляете публичную функцию — добавьте тест и обновите README.
4. Откройте PR с коротким описанием, что и зачем меняется.
